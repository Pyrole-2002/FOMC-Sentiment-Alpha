# fed-sentiment-alpha

**Question:** does the *change* in the sentiment of FOMC communications carry
short-horizon, tradable information about US equity returns?

**Answer format:** a Spearman Information Coefficient with a bootstrap
confidence interval — not a hero backtest. A rigorously demonstrated *negative*
result is a valid and intended outcome. See [PLAN.md](PLAN.md) §1.3 and §5.5.

## Setup

Requires [`uv`](https://docs.astral.sh/uv/) and an NVIDIA driver (GPU optional —
see below).

```bash
uv sync
```

That creates `.venv` on Python 3.12 and installs the locked dependency graph
from `uv.lock`. Nothing else is needed: no system CUDA Toolkit, no manual
`pip install torch`.

Verify the environment:

```bash
uv run pytest
```

Verify the GPU specifically:

```bash
uv run python scripts/check_gpu.py
```

### Why `uv` and a lockfile

PLAN.md §5 rests on the claim that these results are reproducible. A hand-written
`requirements.txt` pinning `pandas>=2.0` does not deliver that — a reader six
months from now resolves different versions. `uv.lock` pins the exact version
**and hash** of every package and every transitive dependency, so the environment
is byte-reproducible. It also lets the CUDA-specific torch index be declared
*in* `pyproject.toml`, which `pip` cannot express.

A conventional `requirements.txt` is exported for readers who want one:

```bash
uv export --no-hashes --format requirements-txt > requirements.txt
```

### CUDA notes (RTX 50-series / Blackwell)

The RTX 5070 Ti is **compute capability `sm_120`**. PyTorch wheels from the
`cu126` index and earlier contain **no sm_120 kernels** — they install cleanly,
report `torch.cuda.is_available() == True`, and then fail at the first matmul
with `no kernel image is available for execution on the device`.

`pyproject.toml` therefore pins torch to the **`cu128`** index explicitly. A
CUDA 13.x display driver runs a 12.8 runtime fine (newer driver, older runtime
is the supported direction).

**The GPU is optional.** Everything resolves device at runtime
(`device: auto` in `config.yaml`), so the repo runs unchanged on a CPU-only
machine. FinBERT over ~250 statements takes a few minutes on CPU versus seconds
on GPU; the GPU only becomes load-bearing for the Phase 5 minutes corpus
(~60–90k sentences) and for any model larger than FinBERT.

`src/alpha_signal.py` is named differently from PLAN.md §6.1's `signal.py`

very hard to diagnose.

## Two corrections applied to PLAN.md

Both are documented inline in `config.yaml`.

**1. `Adj Close` cannot give you an adjusted Open.** PLAN.md §4.3 enters at the
"Adjusted Open" while Appendix A sets `price_field: "Adj Close"`. These are
incompatible — with `auto_adjust=False`, yfinance returns raw OHLC plus one
extra `Adj Close` column; there is no `Adj Open`. Entering on a raw Open and
exiting on an adjusted Close mixes two price bases and injects every SPY
dividend (~1.3%/yr, compounded over 30 years) as a phantom loss. Fixed by
`auto_adjust: true`, which back-adjusts all four OHLC columns consistently.

**2. "Next trading day" is not `release_date + 1`.** The 2020-03-15 emergency
cut was announced on a **Sunday evening**; the 2008-10-08 coordinated cut was
released at **07:00 ET**, before the open. `release_datetime` is therefore a
timezone-aware `America/New_York` timestamp, and the entry lookup is a
`searchsorted(..., side="right")` into the actual SPY trading-day index.

## Conventions

- **`data/raw` is immutable.** Files are written once, never edited. Every fetch
  is logged to `data/raw/manifest.csv` with its URL, sha256, byte count and UTC
  timestamp, so `verify_manifest()` can prove the corpus has not drifted.
- **Every transformation states what timestamp its inputs are valid as-of.**
- **`config.yaml` is pre-registration.** Changing a primary value after seeing
  results fails `test_preregistered_primary_values`, forcing the change to be
  deliberate and reviewed rather than quiet.
